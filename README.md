# 🐟 ماهی تنور — سفارش آنلاین ماهی تازه

فروشگاه/سفارش آنلاین ماهی با پنل مدیریت کامل — ساخته‌شده با **Next.js 16 + TypeScript + Tailwind CSS 4 + Prisma (SQLite)**

> همه‌چیز داینامیک است: ماهی‌ها، دسته‌ها، حَشوها، بازه‌های زمانی، روش‌های ارسال، بنرها و تنظیمات سایت — همگی از **پنل مدیریت** قابل ویرایش‌اند.

---

## 🚀 اجرا روی سیستم خودتان (از صفر)

### پیش‌نیازها

| ابزار | حداقل نسخه | توضیح |
|---|---|---|
| **Bun** (پیشنهادی) | 1.1+ | سریع‌ترین راه — [نصب Bun](https://bun.sh) |
| یا Node.js | 20.9+ | اگر Bun نمی‌خواهید |
| Git | — | برای clone |

### روش ۱: با Bun (پیشنهادی)

```bash
# 1) نصب پکیج‌ها
bun install

# 2) ساخت دیتابیس + دیتای تستی (یک دستور، همه‌کاره)
bun run setup

# 3) اجرای برنامه
bun run dev:local
```

### روش ۲: با npm / Node.js

```bash
# 1) نصب پکیج‌ها
npm install

# 2) ساخت دیتابیس + دیتای تستی
npm run setup:node

# 3) اجرای برنامه
npm run dev:local
```

بعد از اجرا، مرورگر را باز کنید: **http://localhost:3000**

> دستور `setup` سه کار پشت‌سرهم انجام می‌دهد:
> 1. `prisma generate` — ساخت Prisma Client
> 2. `prisma db push` — ساخت فایل دیتابیس `db/custom.db` از روی اسکیمای `prisma/schema.prisma`
> 3. اجرای `prisma/seed.ts` — پر کردن دیتابیس با **دیتای تستی کامل**

## 📦 دیتای تستی (Seed) شامل چه چیزهایی است؟

| بخش | محتوا |
|---|---|
| ⚙️ تنظیمات سایت | نام، شعار، کاور، بنر، آدرس، ساعت کاری، تلفن، اینستاگرام |
| 🐟 دسته‌بندی‌ها | ۶ دسته: قزل آلا، کپور، شیر ماهی، سالمون، سوف، فیل ماهی |
| 🍽️ ماهی‌ها | ۸ آیتم با عکس، توضیح و قیمت (قزل آلا کبابی، کپور شکم‌پر، سالمون، …) |
| 🥗 حَشوها | ۵ گزینه با قیمت: سبزیجات، لیمو و سس، گوجه و قارچ، پیاز، سیر |
| ⏰ بازه‌های زمانی | ۱۱:۰۰–۱۳:۰۰ (ظهر) و ۱۸:۰۰–۲۰:۰۰ (عصر) |
| 🚚 روش دریافت | تحویل در محل (رایگان)، پیک رفت و برگشت (۵۰ هزار)، پیک فقط رفت (۳۰ هزار) |
| 👤 پروفایل | کاربر «احسان» |
| 📍 آدرس‌ها | ۳ آدرس نمونه با مختصات GPS (اصفهان) |
| ❤️ علاقه‌مندی‌ها | ۴ ماهی |
| 🧾 سفارش‌ها | ۳ سفارش نمونه (در حال آماده‌سازی / تحویل‌شده) با لوکیشن |

همه عکس‌های دیتای تستی **داخل خود پروژه** (`public/assets/seed/`) هستند؛ یعنی بدون اینترنت هم همه‌چیز کامل نمایش داده می‌شود.

## 🔁 ریست کردن دیتای تستی

اگر خواستید دیتابیس را به حالت اولیه برگردانید (مثلاً بعد از تغییرات زیاد در پنل ادمین):

```bash
# فایل دیتابیس را حذف کنید (ویندوز: del db\custom.db)
rm db/custom.db

# دوباره بسازید و seed کنید
bun run setup          # یا: npm run setup:node
```

## 🛠️ دستورهای پرکاربرد

| دستور | کار |
|---|---|
| `bun run dev:local` | اجرای برنامه روی `localhost:3000` (مناسب سیستم شخصی) |
| `bun run setup` | ساخت Prisma Client + دیتابیس + دیتای تستی (Bun) |
| `npm run setup:node` | همان setup برای npm/Node |
| `bun run db:seed` | فقط اجرای مجدد seed (Bun) |
| `npm run db:seed:node` | فقط اجرای مجدد seed (npm) |
| `bun run db:push` | اعمال تغییرات `prisma/schema.prisma` روی دیتابیس |
| `bun run lint` | بررسی کیفیت کد با ESLint |

> **نکته:** seed **تکرارپذیر (idempotent)** است؛ اجرای دوباره‌ی آن آیتم‌های موجود را به‌روزرسانی می‌کند و داده‌های تکراری نمی‌سازد. سفارش‌ها/آدرس‌ها/علاقه‌مندی‌ها فقط وقتی ساخته می‌شوند که جدول خالی باشد.

## 🧭 راهنمای برنامه

- **نوار پایین:** خانه (وسط، دکمه قطره‌ای)، ماهی‌ها، سفارش‌ها، پروفایل، تنظیمات

  - ویرایش همه محتوا: تنظیمات سایت، دسته‌ها، ماهی‌ها، حَشوها، زمان‌ها، روش‌های دریافت، سفارش‌ها

- **آدرس با GPS:** موقعیت مکانی از طریق مرورگر (Chrome) گرفته می‌شود — باید لوکیشن گوشی/سیستم روشن باشد و به مرورگر اجازه دسترسی بدهید

## 📁 ساختار مهم پروژه

```
prisma/
  schema.prisma        # اسکیمای دیتابیس (SQLite)
  seed.ts              # دیتای تستی
db/
  custom.db            # فایل دیتابیس (بعد از setup ساخته می‌شود — در گیت نیست)
src/
  app/
    page.tsx           # تک‌صفحه اصلی (کل اپ همین‌جا رندر می‌شود)
    api/               # API Routes (app, orders, addresses, admin, upload, …)
  components/mahi/     # کامپوننت‌ها و ویوهای اپ (Home, Menu, Cart, Admin, …)
  lib/                 # ابزارها (db, format, geo)
public/
  assets/seed/         # عکس‌های دیتای تستی (لوکال)
  uploads/             # عکس‌های آپلودی از پنل ادمین (در گیت نیست)
```

## ⚠️ نکته‌ها

- فایل `.env` شامل `DATABASE_URL=file:../db/custom.db` است (مسیر نسبی — روی هر سیستمی کار می‌کند). اگر در ریپو نبود، از `.env.example` کپی بگیرید.
- `db/custom.db` و `public/uploads/` در گیت نیستند؛ چون دیتابیس و عکس‌های آپلودی مخصوص هر سیستم است.
- برای دیپلوی پروداکشن (`next build`) در ویندوز، از WSL یا Git Bash استفاده کنید (اسکریپت build از دستورهای لینوکسی `cp` استفاده می‌کند).
